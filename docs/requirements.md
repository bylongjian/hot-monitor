# hot-monitor 热点监控工具 — 需求文档

> 版本：v1.5  
> 日期：2026-04-21  
> 状态：Phase 1 已完成（Web 版 + 状态驱动刷新 + 账号监控 + 时区修正 + 体验优化 + 热点详情增强）

---

## 1. 项目背景

作者是 AI 编程博主，需要**第一时间感知 AI 领域热点**（大模型更新、新工具发布、行业动态等），以便及时创作内容。  
当前痛点：依赖人工刷社交媒体，效率低、容易错过。  
目标：构建一套自动化热点监控工具，发现热点后**主动推送通知**，让作者走在吃瓜第一线。

新增目标：在列表卡片里尽量展示足够的上下文，减少人工跳转原始站点才能判断信息价值的次数。

---

## 2. 用户角色

| 角色           | 描述                                                       |
| -------------- | ---------------------------------------------------------- |
| 博主（主用户） | 配置关键词与监控范围，接收通知，查看热点 Dashboard         |
| AI Agent       | 通过 Agent Skills 接口查询热点、添加监控，实现 AI 辅助监控 |

---

## 3. 核心功能需求

### 3.1 关键词监控（主动追踪）

- 用户可**手动添加关键词**（如 "GPT-5"、"Claude 4"、"Gemini Ultra"）
- 支持添加**平台账号监控**（如 B站 / 微博 / 知乎 / X / GitHub 账号）
- 系统按配置的频率定期搜索该关键词相关的最新内容
- **利用 AI 识别**：过滤无关、假冒或低质量信息（如转发、重复、标题党）
- 发现真实相关内容时，**第一时间发送通知**（邮件）
- 每个关键词可独立启用/停用
- 支持查看某关键词的历史命中记录
- 列表中可查看最近一次检查时间，时间文案采用常见产品风格展示

### 3.2 热点自动发现（范围巡逻）

- 用户可配置**监控范围**（如 "AI编程"、"大模型"、"开源工具"）
- 系统定期在该范围内**自动发现热点**，无需预先指定关键词
- AI 对采集内容进行**热度评分**（1-10分）、**摘要提取**
- 热点展示在 Dashboard 上，按热度/时间排序
- 高热度（≥8分）内容自动触发通知
- 手动扫描与定时扫描共享同一套执行状态，避免重复触发
- 扫描完成后页面自动刷新，不再依赖固定间隔盲刷
- 热点详情尽量在列表中直接可判读：优先展示发布时间，展开后可查看原始描述、AI 相关性理由和互动指标

### 3.3 Web Dashboard

- 响应式设计，PC/手机均可正常使用
- **整体视觉风格**：深色仪表盘（背景 `#0b0f1a`），顶部导航栏品牌名 "HotPulse"，卡片半透明毛玻璃效果
- 页面内容：
  - **热点雷达（Dashboard）**：
    - 顶部 4 张统计卡（总热点 / 今日新增 / 紧急热点≥9分 / 监控词数量）
    - 热点卡片列表，每张卡片含：
      - 热度等级徽章（CRITICAL ≥9 / HIGH ≥7 / MED ≥5 / LOW）、来源字母头像、来源类型、分类标签、已推送标记
      - 标题（外链）、AI 摘要（"AI 摘要" 前缀标注）
      - 统一互动指标（如点赞、评论、转发、星标，有则显示）与关键词相关性分数
      - 底部：优先展示发布时间；若缺失则明确回退到抓取时间；支持展开详情
      - 展开区：原始描述、AI 相关性理由、来源专属互动指标、原始链接、完整抓取时间
    - 排序标签页（最新发现 / 热度最高 / 命中优先 / 未通知优先）
    - 筛选芯片（全部 / 中热 / 高 / 极热），带活跃筛选计数与重置按钮
    - 组合筛选：来源、是否关键词命中、时间范围、标签、关键词搜索
    - 筛选状态写入 URL，刷新页面后保留当前视图
    - 来源和标签列表默认折叠，仅在用户点击“更多”后展开全部
    - 支持一键展开/折叠全部热点详情
  - **关键词管理**：增删关键词，查看每个词的状态与命中历史
    - 列表筛选：启用状态、类型、平台、创建时间排序、搜索
    - 列表筛选状态写入 URL，刷新页面后保留
    - 命中记录与热点页共用同一套详情卡片，并支持批量展开
  - **设置页**：通知配置（邮件）、扫描频率、最低入库热度、OpenRouter API Key 配置等
- 导航方式：顶部 Tab 导航（热点雷达 / 监控词 / 设置）；移动端同时支持底部 Tab 导航
- 顶部状态区可见调度器运行状态、扫描结果提示和最近扫描时间

### 3.4 Agent Skills 封装（二期）

- 将核心功能封装为 `.prompt.md` 技能文件
- 技能能力：
  - 查询最新热点列表
  - 查询某关键词下的最近命中
  - 添加/删除关键词监控
  - 手动触发一次扫描
- 其他 AI（如 GitHub Copilot、Claude）可通过调用该技能实现自动化监控

## 4. 通知需求

| 通知渠道     | 优先级       | 说明                            |
| ------------ | ------------ | ------------------------------- |
| 邮件（SMTP） | P0，必须实现 | 支持 Gmail、QQ 邮箱等 SMTP 配置 |
| Webhook      | P1，后续迭代 | 可对接 Telegram Bot、Bark、飞书 |

**通知内容**包含：热点标题、AI 摘要、来源链接、热度分、触发时间。

## 5. 数据来源

| 来源              | 类型          | 说明                                                                        |
| ----------------- | ------------- | --------------------------------------------------------------------------- |
| X/Twitter AI 热点 | Nitter/Google | Nitter 实例抓取 AI 关键账号动态，不可用时回退 Google News 搜索              |
| RSS 聚合          | RSS Feed      | OpenAI Blog、Google DeepMind、HuggingFace、TechCrunch AI、VentureBeat AI 等 |
| Hacker News API   | 免费公开 API  | https://hacker-news.firebaseio.com/v0/                                      |
| Reddit            | JSON API      | r/MachineLearning、r/artificial 热门帖子                                    |
| GitHub Trending   | HTML 解析     | 每日热门仓库                                                                |
| 搜索引擎          | 无 Key 搜索   | DuckDuckGo + Bing News，关键词实时搜索                                      |

> **内容质量机制**：48 小时时效性过滤（发布时间过旧的内容在 AI 分析前自动丢弃）+ AI 时效性评分（旧闻/科普/广告评分 1-3 分）

> **时间语义要求**：只有抓取源明确提供发布时间时才写入发布时间字段；否则前端必须明确回退到抓取时间，避免误导用户。

---

## 6. AI 分析需求

- 接入 **OpenRouter**，默认模型：`deepseek/deepseek-v3.2`
- AI 分析任务：
  1. **真实性判断**：判断内容是否为真实热点（非转发、非广告、非假冒）
  2. **关键词相关性判断**：与用户设定关键词的相关度（0-10）
  3. **热度评分**：综合来源权威度、讨论量、新颖度（0-10）
  4. **摘要生成**：100字以内中文摘要
  5. **标签提取**：提取 2-4 个关键标签

## 7. 非功能需求

| 需求       | 说明                                                               |
| ---------- | ------------------------------------------------------------------ |
| 轻量化     | 无需 Docker/Redis/Kafka；单进程运行                                |
| 易部署     | `pip install -r requirements.txt` + 填写 `.env` 即可运行           |
| 配置化     | 通过 `.env` 文件配置所有敏感信息；扫描频率可在 UI 中调整           |
| 安全性     | API Key 不硬编码；SMTP 密码环境变量注入                            |
| 可靠性     | 单次抓取失败不影响整体运行；错误写入日志                           |
| 可感知性能 | 扫描中短轮询、空闲时长轮询；减少常驻动画与无效刷新                 |
| 时间一致性 | API 时间统一输出 UTC，前端按本地时区正确展示                       |
| 开发体验   | VS Code 集成终端默认使用 **Git Bash**，保证 Shell 脚本跨平台一致性 |

## 8. 不在范围内（Out of Scope v1.0）

- 多用户系统 / 账号体系
- 抖音、微博等平台的爬虫（需要特殊处理）
- 移动端 App
- 付费功能

> 注：X/Twitter 已通过 Nitter 实例 + Google News 回退方案实现，不再列为 Out of Scope。
